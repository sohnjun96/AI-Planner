## 23:18 - 일정 알림 창 재사용 및 동시 알림 순서 처리

### 변경 요약

- 일정 알림과 확장 아이콘 클릭 시 기존 플래나이 탭을 재사용하고 해당 창을 활성화한다. 최소화한 창은 복원한다.
- 탭 탐색·생성·이동을 직렬화하고 실제 URL 이동 완료를 기다려 동시 알림의 중복 탭 생성 및 알림 덮어쓰기를 방지한다.
- 대기 일정 ID를 URL에 유지하고 닫기·상태 변경 시 확인한 일정만 제거하여 다음 알림을 표시한다. 삭제·완료·취소한 대기 일정은 건너뛴다.
- 루트 백그라운드 스크립트를 배포용 소스와 일치시키고 내부망 배포 파일을 재빌드했다.

### 주요 영향 파일

- `public/background.js`, `background.js`, `public/manifest.json`
- `src/pages/DashboardPage.tsx`, `src/utils/reminderQueue.ts`
- `tests/scheduleReminders.test.ts`, `scripts/test-schedule-reminders.mjs`
- `scripts/run-tests.mjs`, `scripts/build-extension.mjs`, `package.json`
- `dist/background.js`, `dist/manifest.json`, `dist/assets/app.js`

### 검증

- `npm test`: 기존 테스트 및 동시 알림·중복 제거·창 활성화 오류·알림 제거 회귀 테스트 통과.
- `npm run build`: 타입 검사 및 내부망 빌드 통과.
- `npm run lint`: 통과.
- `node scripts/test-schedule-reminders.mjs`: 별도 Chromium 프로필에서 실제 배포 확장을 로드하여 기존 탭 재사용, 닫힌 상태의 동시 알림 단일 탭 생성, 순차 닫기, 완료 후 다음 알림 표시 검증 통과.

### 주의사항

- 기존 탭 URL 검색에 필요한 `tabs` 권한을 배포 매니페스트와 빌드 검증에 추가했다. 해당 권한은 브라우저 탭 정보 접근 범위를 넓히므로 업데이트 시 권한 안내가 표시될 수 있다. 코드의 조회 대상은 자기 확장의 `index.html`로 제한하며 외부 전송은 추가하지 않았다.
- 적용하려면 확장 프로그램을 새로고침하고 기존 플래나이 페이지도 새로고침해야 한다. Chrome 최소 버전은 유지한다.
- 브라우저 테스트는 임시 프로필과 가상 일정만 사용하며 실제 사용자 프로필·일정에 접근하지 않는다.

## 23:45 - 일정 알림의 연기하기 메뉴 추가

### 변경 요약

- 알림창의 하단 버튼을 완료하기·취소하기·연기하기로 변경했다.
- 연기하기를 누르면 아래에 내일로 연기·3일 뒤로 연기·일주일 뒤로 연기 옵션이 펼쳐진다. 다시 누르면 접힌다.
- 기존 일정 시작일에서 1·3·7일을 이동하고 시작 시각, 일정 길이와 상태를 유지한다. 저장 후 알림을 닫고 대기 중인 다음 알림을 표시한다.
- 변경된 일정의 알림은 기존 알림 설정에 따라 다시 예약된다. 저장 중에는 버튼을 비활성화하고 실패하면 오류를 표시한다.

### 주요 영향 파일

- `src/components/ScheduleReminderModal.tsx`
- `src/pages/DashboardPage.tsx`, `src/index.css`
- `scripts/test-schedule-reminders.mjs`
- `dist/assets/app.js`, `dist/assets/app.css`

### 검증

- `npm run build`: 타입 검사 및 내부망 배포 빌드 통과.
- `npm test`, `npm run lint`, `git diff --check`: 통과.
- `npm run test:reminders`: 실제 Chromium에서 세 연기 옵션의 날짜 변경, 일정 길이·상태 유지, 변경된 시작 시각 5분 전 알람 재예약 및 기존 알림 순서 처리 검증 통과.
- 390px 화면에서 펼쳐진 메뉴를 캡처하여 버튼·문구 잘림 없이 표시되는 것을 확인했다.

### 주의사항

- 데이터 스키마·확장 권한 변경 없음. 날짜는 기존 일정 시작일 기준으로 이동한다.
- 기존 플래나이 페이지를 새로고침하면 변경된 화면을 사용할 수 있다.

## 23:49 - 일정 연기 이력을 내용에 자동 기록

### 변경 요약

- 알림창에서 일정을 연기하면 내용 끝에 `[일정 연기] 기존 일시 → 변경 일시` 메모를 추가한다.
- 종료 시각이 있는 일정은 기존·변경 후 시작과 종료 일시를 함께 기록한다.
- 기존 내용을 유지하고 반복 연기 시 이력을 누적한다. 날짜 변경과 메모는 같은 일정 저장 작업으로 반영한다.

### 주요 영향 파일

- `src/pages/DashboardPage.tsx`
- `scripts/test-schedule-reminders.mjs`
- `dist/assets/app.js`

### 검증

- `npm run build`: 타입 검사 및 내부망 빌드 통과.
- `npm run lint`: 통과.
- `npm run test:reminders`: 실제 Chromium에서 1·3·7일 연기 시 정확한 전후 일시 기록, 빈 내용에 첫 메모 추가 및 기존 이력 보존·누적 검증 통과. 날짜 변경과 알림 재예약 회귀 검증도 통과.

### 주의사항

- 데이터 스키마·권한 변경 없음. 메모는 앱의 기존 일시 표시와 동일한 로컬 시간대를 사용한다.
- 기존 플래나이 페이지를 새로고침하면 적용된다.
