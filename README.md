# 플래나이(PLANAI)

> 쪽지로 쏟아지는 마감·제출·취합 일정과 업무 메모를 한곳에 모아, AI가 분류·정리·검색·브리핑을 돕는 로컬 우선(Local-first) 업무 플래너.

플래나이(PLANAI)는 Plan과 AI를 결합한 이름으로, AI와 함께 계획하고 정리하며 실행하는 지능형 업무 플래너입니다. 모든 데이터는 브라우저 안(IndexedDB)에 저장되어 로그인도, 서버 계정도 필요 없고, AI 기능은 사용자가 지정한 LLM 엔드포인트(로컬 모델 포함)로만 연결됩니다.

React 19 + TypeScript + Vite로 만든 SPA이며, Chrome 확장(Manifest V3)으로도 빌드됩니다.

## 왜 만들었나

일정 관리는 날짜를 저장하는 문제가 아니라 **지금 뭘 먼저 할지 판단하는** 문제입니다. 실제 업무에서는 이런 일이 반복됩니다.

- 제출·회의·점심·연가·출장처럼 성격이 다른 일정이 섞이면 우선순위를 놓칩니다.
- 완료한 일과 지나간 일이 현재 할 일을 가립니다.
- "점심은 보통 11:30, 제출은 18:00" 같은 개인 규칙을 매번 손으로 입력합니다.
- "내일 10시에 보고서 제출 추가"라고 말하고 싶은데 입력 폼은 여전히 번거롭습니다.

그래서 플래나이는 **달력에서 전체 흐름을 보고 → 자연어로 초안을 만들고 → 확인해서 적용**하는 흐름을 중심에 뒀습니다. 반복되는 습관은 AI가 재사용 규칙으로 제안하고, 승인하면 다음부터 자동 적용됩니다.

## 대시보드 — 이번 달을 한 장에

대시보드는 월간 달력을 중심으로, 목록·주간·월간 보기를 전환합니다(기본 월간).

일정은 상태로 구분됩니다. **미완료**는 프로젝트 색과 또렷한 테두리로 강조되고, 완료·취소는 흐리게 가라앉아 남은 일을 방해하지 않습니다. 연가는 날짜 셀이 초록, 출장은 파랑으로 물들고, 점심·중요 같은 표식이 셀에 붙습니다. 지난 완료 업무는 기본으로 숨기되 설정에서 켤 수 있습니다.

날짜를 클릭하면 **달력과 메모 사이에 그 날 일정만** 목록으로 열립니다. 상태 배지(전체·미완료·보류·완료·취소)가 그대로 필터라, 클릭 한 번으로 걸러 볼 수 있고 미완료 외 항목은 회색으로 눌러 구분됩니다.

**우클릭으로 빠르게**: 달력 날짜를 우클릭하면 AI 일정 추가 / 직접 추가 / 연가 설정을, 일정 카드를 우클릭하면 완료·보류·수정·AI 수정·복제·삭제를 바로 처리합니다. 상단 `AI 일정 추가`는 단축키 `A` 또는 `Ctrl+Shift+N`으로도 열립니다.

오늘의 마지막 미완료·보류 일정을 완료하면 **“오늘 일정은 모두 마쳤어요”** 축하 배너와 짧은 색종이 효과가 나타납니다. 취소된 일정이나 일정이 없는 날에는 발동하지 않으며, 운영체제에서 애니메이션 줄이기를 켠 경우에는 정적인 배너만 표시합니다.

## 노트 — 쓰고, 묶고, 이어 보기

<p align="center">
  <img src="docs/images/notes.png" alt="노트 스택 보기" width="820">
</p>

마크다운 노트를 프로젝트·세부 항목으로 정리합니다. 왼쪽 탐색기에서 카테고리를 고르면 오른쪽에 해당 노트들이 **위아래로 이어져** 펼쳐지고, 본문은 마크다운으로 렌더링되며 체크박스는 그 자리에서 토글됩니다.

- 상단 `노트 추가`는 제목 없이 내용만 빠르게 받습니다. AI 연결이 있으면 본문을 읽어 짧은 제목을 만들고, 연결 실패 시에는 첫 유효 문장을 안전한 대체 제목으로 사용합니다.
- 편집기 안에서는 제목이 본문 첫 줄을 **자동으로 따라오되**, 직접 고치면 그때부터 고정됩니다.
- 프로젝트·세부 항목 분류는 백그라운드에서 자동 추천되고, 관련 노트도 함께 탐색합니다.
- 카드를 드래그해 순서를 바꾸고, 편집한 내용은 다른 노트로 넘어가도 **자동 저장**됩니다.
- 노트를 일정과 연결하면 양쪽에서 서로를 오갈 수 있고, 전체 미완료 체크리스트를 한곳에 모아 볼 수 있습니다.
- 수동 저장·자동 저장·AI 편집 버전을 비교하고 이전 내용으로 복원할 수 있습니다.
- 보관한 노트는 별도 보관함 뷰로 분리되어 평소 목록을 어지럽히지 않습니다.

## AI로 하는 일

### Tool Calling 구현 문서

AI가 로컬 일정·노트 데이터를 어떤 방식으로 조회하고, 결과를 어떻게 검증·재사용하며, 일정 변경을 왜 초안으로만 제안하는지 정리했습니다. 도구별 인자·반환값·안전장치까지는 [Tool Calling 구현 가이드](docs/TOOL_CALLING.md)에서 확인할 수 있습니다.

플래나이의 AI는 네이티브 function calling에 의존하지 않습니다. 대신 **프롬프트로 JSON 스키마를 지시**하고, 모델이 돌려준 도구 호출을 앱이 로컬에서 실행한 뒤 결과를 붙여 다시 물어보는 방식(도구 사용 에이전트는 최대 3라운드)으로 동작합니다. 덕분에 로컬 모델을 포함한 OpenAI 호환 chat completions 엔드포인트와 연결할 수 있습니다.

### 자연어로 일정 관리

<p align="center">
  <img src="docs/images/ai-schedule.png" alt="AI 일정 추가 — 규칙과 초안" width="560">
</p>

"내일 11시반에 김선임과 점심"이라고 쓰면 날짜·시간·프로젝트·종류를 채운 **초안 카드**를 만듭니다. 날짜와 시간을 크게 분리해 빠르게 확인할 수 있고, 원하는 카드만 선택해 반영합니다. AI는 바로 저장하지 않고 초안을 먼저 보여 주므로 잘못된 일정이 그대로 들어가는 일을 줄입니다. 생성·수정·삭제와 기존 일정 검색을 통한 후보 확인까지 지원합니다.

반복될 만한 패턴은 **재사용 규칙**으로 함께 제안합니다. 규칙별 저장·무시 또는 모두 저장·무시를 선택한 뒤 초안을 반영하는 흐름이라, 한 번 정한 습관("점심은 11시반, 점심 약속 프로젝트")은 다음부터 `user.md`에 저장되어 자동 적용됩니다.

### 내 데이터에 질문

<p align="center">
  <img src="docs/images/qa.png" alt="내 노트·일정에 질문" width="560">
</p>

노트와 일정을 검색해 답하고, 근거가 된 항목을 **참고 칩**으로 달아 클릭하면 바로 그 노트나 일정으로 이동합니다. 아래 🔎 줄은 실제로 어떤 도구를 몇 번 호출했는지 보여 줍니다. 모델이 도구를 쓰지 않아도 답할 수 있도록, 매 요청에 노트·일정 제목 목록을 함께 실어 보냅니다.

### 그 밖의 AI 기능

- **AI 브리핑** — 오늘의 핵심, 지연·시간 충돌 주의사항, 관련 최근 노트, 추천 행동을 짧은 마크다운으로 정리하고 노트로 저장
- **노트 → 할 일** — 노트 본문에서 실행 항목을 뽑아 일정으로 등록
- **노트 편집 도구** — 다듬기·요약·구조화·체크리스트 변환 (프롬프트는 설정에서 직접 수정 가능)
- **빠른 노트 제목** — 내용만 적으면 AI가 짧은 한국어 제목을 자동 생성

## 사용 통계와 데이터

<p align="center">
  <img src="docs/images/stats.png" alt="설정 — 사용 통계" width="820">
</p>

설정의 **통계** 탭에서 일정·노트 현황, 브라우저가 배정한 저장 공간, AI 토큰 사용량(오늘/누적)을 확인합니다. 서버가 토큰 수를 주지 않으면 문자 수 기반 추정치로 기록합니다.

설정에서는 AI 엔드포인트·모델·API 키, 주 시작 요일, 시간 표시, 알림, 자동 백업, 일정 종류, 노트 AI 동작, 그리고 `user.md` 개인 규칙을 관리합니다. Chrome 확장에서는 지정한 시간만큼 일정 시작 전에 알림을 띄우고, 알림을 클릭하면 대시보드를 엽니다. 자동 백업은 브라우저 안에 주기적으로 보관되며 설정에서 복원하거나 삭제할 수 있습니다. `user.md`에는 이런 규칙을 저장해 둘 수 있습니다.

```md
- 점심 일정은 시간이 없으면 11:30으로 설정한다.
- 제출 일정은 시간이 없으면 18:00으로 설정한다.
- 점심·식사·밥이 들어가면 프로젝트는 점심 약속, 종류는 식사로 설정한다.
```

전체 데이터는 JSON으로 내보내고 되돌릴 수 있어, 백업과 이전이 파일 하나로 끝납니다.

## 기술 구성

| 영역 | 사용 기술 |
| --- | --- |
| 프론트엔드 | React 19, TypeScript, Vite |
| 라우팅 | React Router 7 (HashRouter) |
| 저장소 | Dexie(IndexedDB) + `useLiveQuery` 반응형 조회 |
| AI 연결 | OpenAI 호환 chat completions (SSE 스트리밍 + JSON 폴백) |
| 배포 | 웹 SPA / Chrome 확장(Manifest V3) |

의도적으로 상태 관리 라이브러리나 UI 프레임워크를 두지 않았습니다. 데이터는 Dexie 라이브 쿼리로 컴포넌트에 흘려보내고, 화면 상태는 React 훅으로만 다룹니다. 스타일은 CSS 디자인 토큰 기반의 단일 `index.css`로 관리합니다. 일반 일정 관리는 완전히 로컬에서 동작하고, AI 서버가 꺼져 있어도 캘린더·노트·프로젝트는 그대로 쓸 수 있습니다.

### 에이전트 구조

모든 에이전트는 공용 인프라를 공유합니다.

- `agentTools.ts` — 읽기 전용 도구 실행기(일정/노트 검색·조회), 중복 호출 캐시, 결과 상한(16건), 잘못된 인자에 대한 교정 피드백
- `agentUtils.ts` — 관대한 JSON 파싱, 표기 편차를 흡수하는 도구 호출 파서(`tool`/`name`/`function.name` 등), 파싱 실패 시 1회 재시도
- `llmClient.ts` — 스트리밍/취소(AbortSignal) 지원, 요청마다 토큰 사용량 기록

| 에이전트 | 하는 일 | 도구 |
| --- | --- | --- |
| `scheduleAgent` | 자연어 → 일정 초안 + 재사용 규칙 | 일정 검색·조회, 프로젝트·종류 목록 |
| `qaAgent` | 노트·일정 질의응답 | 노트/일정 검색·조회 |
| `notesAgent` | 노트 편집·요약·통합, 관련 노트 탐색 | 노트/버전/연결 일정 조회 |
| `briefingAgent` | 아침 브리핑(단발 요청) | 없음 |
| `noteTitleAgent` | 빠른 추가 노트의 제목 생성(단발 요청) | 없음 |

## 시작하기

```bash
npm install
npm run dev          # http://localhost:5173
```

빌드 / 미리보기:

```bash
npm run build        # 타입 체크 + 확장 번들 (dist/)
npm run preview      # 프로덕션 미리보기
npm run typecheck    # 타입 체크만
npm run lint         # ESLint 검사
```

**Chrome 확장으로 설치**: `chrome://extensions` → 개발자 모드 켜기 → "압축해제된 확장 프로그램을 로드" → 이 프로젝트의 `dist` 폴더 선택.

**AI 연결**: 설정 → AI 연결에서 OpenAI 호환 엔드포인트와(필요 시) API 키를 입력하세요. 로컬 모델도 엔드포인트만 맞으면 그대로 동작하고, 비워 두면 일반 기능은 그대로 쓸 수 있습니다.

## 프로젝트 구조

```
src/
├── agent/          # LLM 클라이언트 + 일정·노트·질의·브리핑·제목 AI + 공용 도구/유틸
├── components/     # 재사용 UI (노트 카드·에디터, AI 워크스페이스, 달력, 토스트 등)
├── context/        # AppDataContext — Dexie 기반 전역 데이터/CRUD
├── pages/          # 대시보드 · 노트 · 프로젝트 · 설정
├── utils/          # 날짜, 노트 제목, 프로젝트 정렬, AI 사용량 등
├── db.ts           # Dexie 스키마
├── models.ts       # 도메인 타입
└── index.css       # 디자인 토큰 + 전체 스타일
```
