# 플래나이 (PLANAI)

> 쪽지로 쏟아지는 마감·제출·취합 일정과 업무 메모를 한곳에 모으고, AI가 정리·검색·브리핑을 돕는 로컬 우선(Local-first) 업무 플래너.

캘린더 앱, 메모장, 제출 마감표를 오가지 않아도 오늘 할 일과 앞으로의 일정을 한 화면에서 관리하도록 만들었습니다. 데이터는 브라우저 안(IndexedDB)에만 저장되어 로그인도 서버 계정도 없고, AI 기능은 사용자가 지정한 LLM 엔드포인트로만 연결됩니다. AI 서버가 꺼져 있어도 달력·노트·프로젝트는 그대로 동작합니다.

웹앱(React 19 + TypeScript + Vite)이면서 Chrome 확장(Manifest V3)으로도 빌드됩니다.

## 화면 구성

앱은 **대시보드 · 노트 · 프로젝트 · 완료 기록 · 설정** 다섯 화면으로 이뤄집니다. 상단 바에는 어디서든 쓸 수 있는 `질문` · `노트 추가` · `AI 일정 추가`(단축키 `A` 또는 `Ctrl+Shift+N`)가 있습니다.

### 대시보드 — 오늘과 이번 달을 한 장에

월간 달력을 중심으로 **목록 · 주간 · 월간** 보기를 전환합니다(기본 월간).

- **상태로 구분** — 미완료는 프로젝트 색과 또렷한 테두리로, 완료·취소는 흐리게 가라앉습니다. 연가는 셀이 초록, 출장은 파랑으로 물들고 점심·중요 표식이 붙습니다. 지난 완료 일정은 기본으로 숨기되 설정에서 켤 수 있습니다.
- **선택한 날짜** — 달력과 메모 사이에 그 날 일정만 목록으로 열립니다. 상태 배지(전체·미완료·보류·완료·취소)가 그대로 필터이고, 미완료 외 항목은 회색으로 눌러 구분됩니다.
- **우클릭으로 바로** — 날짜를 우클릭하면 AI 일정 추가 / 직접 추가 / 연가 설정을, 일정 카드를 우클릭하면 완료·보류·수정·AI 수정·복제·삭제를 처리합니다.
- **드래그 이동** — 일정 카드를 다른 날짜로 끌어 옮길 수 있습니다.
- 오늘의 마지막 미완료·보류 일정을 끝내면 **"오늘 일정은 모두 마쳤어요"** 배너와 짧은 색종이 효과가 나타납니다. 운영체제에서 애니메이션 줄이기를 켜 두면 정적인 배너만 표시됩니다.
- 데이터가 없을 때는 첫 일정·첫 노트를 만드는 안내가 먼저 보입니다.

### 노트 — 쓰고, 묶고, 이어 보기

<p align="center">
  <img src="docs/images/notes.png" alt="노트 이어보기" width="820">
</p>

마크다운 노트를 프로젝트·세부 항목으로 정리합니다. 왼쪽 탐색기에서 카테고리를 고르면 오른쪽에 해당 노트들이 **위아래로 이어져** 펼쳐집니다.

- 상단 `노트 추가`는 제목 없이 내용만 빠르게 받고, AI가 짧은 제목을 붙입니다(연결 실패 시 첫 문장을 대체 제목으로 사용).
- 편집기에서는 제목이 본문 첫 줄을 자동으로 따라오다가, 직접 고치면 그때부터 고정됩니다.
- 프로젝트·세부 항목 분류와 관련 노트 탐색은 백그라운드에서 자동으로 이뤄집니다.
- 카드를 드래그해 순서를 바꾸고, 편집 내용은 다른 노트로 넘어가도 **자동 저장**됩니다.
- 노트를 일정과 연결하면 양쪽에서 서로를 오갈 수 있고, 미완료 체크리스트를 한곳에 모아 볼 수 있습니다.
- 수동 저장·자동 저장·AI 편집 버전을 비교하고 이전 내용으로 되돌릴 수 있습니다.
- 보관한 노트는 별도 뷰로 분리되어 평소 목록을 어지럽히지 않습니다.

## AI 기능

플래나이의 AI는 네이티브 function calling에 의존하지 않습니다. **프롬프트로 JSON 스키마와 도구 목록을 지시**하고, 모델이 돌려준 도구 호출을 앱이 로컬에서 실행한 뒤 결과를 붙여 다시 물어보는 방식(도구 사용 에이전트는 최대 3라운드)으로 동작합니다. 덕분에 로컬 모델을 포함한 OpenAI 호환 엔드포인트와 폭넓게 연결됩니다.

| 기능 | 하는 일 |
| --- | --- |
| **AI 일정 추가** | 자연어를 일정 초안으로 변환. 생성·수정·삭제와 기존 일정 검색까지. 반복되는 기준은 재사용 규칙으로 제안 |
| **질문** | 노트와 일정을 검색해 답변. 근거를 참고 칩으로 제시하고, 어떤 도구를 몇 번 호출했는지 표시 |
| **AI 브리핑** | 오늘의 핵심, 지연·시간 충돌 주의사항, 관련 노트, 추천 행동을 정리하고 노트로 저장 |
| **노트 편집** | 다듬기·요약·구조화·체크리스트 변환. 프롬프트는 설정에서 직접 수정 가능 |
| **노트 → 할 일** | 노트 본문에서 실행 항목을 뽑아 일정으로 등록 |

### 초안을 먼저 보여 준다

<p align="center">
  <img src="docs/images/ai-schedule.png" alt="AI 일정 추가 — 초안과 규칙" width="560">
</p>

AI는 일정을 바로 저장하지 않습니다. 날짜와 시간을 크게 분리한 **초안 카드**를 먼저 보여 주고, 원하는 항목만 골라 반영합니다. 잘못된 일정이 그대로 들어가는 일을 줄이기 위한 설계입니다.

반복될 만한 패턴은 **재사용 규칙**으로 함께 제안합니다. 규칙을 먼저 검토·저장한 뒤 초안을 반영하는 흐름이라, 한 번 정한 습관("제출은 오후 6시", "점심은 점심 약속 프로젝트")은 `user.md`에 남아 다음부터 자동 적용됩니다.

```md
- 점심 일정은 시간이 없으면 11:30으로 설정한다.
- 제출 일정은 시간이 없으면 18:00으로 설정한다.
- 점심·식사·밥이 들어가면 프로젝트는 점심 약속, 종류는 식사로 설정한다.
```

## 설정과 데이터

<p align="center">
  <img src="docs/images/stats.png" alt="설정 — 사용 통계" width="820">
</p>

설정은 **개요 · 기본·일정 · AI 설정 · 알림·백업 · 통계** 다섯 탭입니다.

- **AI 설정** — 엔드포인트·모델·API 키, temperature와 reasoning effort, 노트 AI 동작, `user.md` 개인 규칙
- **기본·일정** — 주 시작 요일, 시간 표시 형식, 지난 완료 일정 표시, 일정 종류 관리
- **알림·백업** — Chrome 확장에서 지정한 시간만큼 일정 시작 전 알림(클릭하면 대시보드로 이동), 브라우저 안 자동 백업 보관·복원
- **통계** — 일정·노트 현황, 브라우저가 배정한 저장 공간, AI 토큰 사용량(오늘/누적). 서버가 토큰 수를 주지 않으면 문자 수 기반 추정치로 기록합니다

전체 데이터는 JSON으로 내보내고 되돌릴 수 있어 백업과 이전이 파일 하나로 끝납니다. 마지막 내보내기가 오래되면 주간 백업 알림이 뜹니다.

## 시작하기

```bash
npm install
npm run dev          # http://localhost:5173
```

```bash
npm run build        # 타입 체크 + 확장 번들 (dist/)
npm run preview      # 프로덕션 미리보기
npm run typecheck    # 타입 체크만
npm run lint         # ESLint 검사
```

**Chrome 확장으로 설치**: `chrome://extensions` → 개발자 모드 켜기 → "압축해제된 확장 프로그램을 로드" → 이 프로젝트의 `dist` 폴더 선택.

**AI 연결**: 설정 → AI 설정에서 OpenAI 호환 엔드포인트와(필요 시) API 키를 입력합니다. 로컬 모델도 엔드포인트만 맞으면 그대로 동작하고, 비워 두면 AI 기능만 비활성화됩니다.

## 기술 구성

| 영역 | 사용 기술 |
| --- | --- |
| 프론트엔드 | React 19, TypeScript, Vite |
| 라우팅 | React Router 7 (HashRouter) |
| 저장소 | Dexie(IndexedDB) v4 스키마 + `useLiveQuery` 반응형 조회 |
| AI 연결 | OpenAI 호환 chat completions (SSE 스트리밍 + JSON 폴백) |
| 배포 | 웹 SPA / Chrome 확장(Manifest V3) |

상태 관리 라이브러리나 UI 프레임워크는 의도적으로 두지 않았습니다. 데이터는 Dexie 라이브 쿼리로 컴포넌트에 흘려보내고 화면 상태는 React 훅으로만 다루며, 스타일은 CSS 디자인 토큰 기반의 단일 `index.css`로 관리합니다.

### 에이전트 구조

모든 에이전트가 공용 인프라를 공유합니다.

- `agentTools.ts` — 읽기 전용 도구 실행기(일정·노트 검색/조회), 중복 호출 캐시, 결과 상한, 잘못된 인자에 대한 교정 피드백
- `agentUtils.ts` — 관대한 JSON 파싱, 표기 편차를 흡수하는 도구 호출 파서(`tool`/`name`/`function.name` 등), 파싱 실패 시 1회 재시도
- `llmClient.ts` — 스트리밍과 취소(AbortSignal), 요청마다 토큰 사용량 기록

| 에이전트 | 역할 | 도구 |
| --- | --- | --- |
| `scheduleAgent` | 자연어 → 일정 초안 + 재사용 규칙 | 일정 검색·조회, 프로젝트·종류 목록 |
| `qaAgent` | 노트·일정 질의응답 | 노트·일정 검색·조회 |
| `notesAgent` | 노트 편집·요약·통합, 관련 노트 탐색 | 노트·버전·연결 일정 조회 |
| `briefingAgent` | 하루 브리핑 (단발 요청) | 없음 |
| `noteTitleAgent` | 빠른 노트의 제목 생성 (단발 요청) | 없음 |

### 프로젝트 구조

```
src/
├── agent/        # LLM 클라이언트 + 5개 에이전트 + 공용 도구·유틸
├── components/   # 재사용 UI (달력, 노트 에디터, AI 워크스페이스, 토스트 등)
├── context/      # AppDataContext — Dexie 기반 전역 데이터와 CRUD
├── pages/        # 대시보드 · 노트 · 프로젝트 · 완료 기록 · 설정
├── hooks/        # 다이얼로그 포커스, 백업 상태
├── utils/        # 날짜, 노트 제목, 일정 충돌, AI 사용량 등
├── db.ts         # Dexie 스키마
├── models.ts     # 도메인 타입
└── index.css     # 디자인 토큰 + 전체 스타일
```

### 문서용 자료
